How a Scenario
is forged.

Three phases build the truth and the initial ensemble; a sixth step samples the observations. Every random draw lives in a separate RNG stream so seeds are reproducible to the bit. What follows is the actual recipe inside Scenario.generate.

Master seed

spawn(4) ⇒ four streams

Every randomness in the diagram comes from one of four independent generators derived from the master seed via np.random.SeedSequence(seed).spawn(4). Reusing only some streams (e.g. fixing rng_xb while varying rng_op) is how scenarios share an ensemble centre but vary their observation network.

rng_op
selects / builds the observation operator at every step
rng_xb
draws the perturbation for Phase 2 (xᵇ construction)
rng_ens
draws per-member perturbations for Phase 3 (Xᵇ)
rng_noise
samples observation noise 𝒩(0, R) at every step k

Phase 01 · reference

The synthetic IC walks onto the attractor.

Models start cold. Lorenz96 starts from a random vector; QGModel starts from a Fourier IC; SWEModel starts from Williamson's solid-body rotation plus Rossby perturbations. None of these are physically realistic states. A long propagation lets transients die and the trajectory settle on the model attractor — the climatology you actually want to assimilate against.

input
x₀ = model.get_initial_condition()
propagate over t ∈ [0, T₁]   with   T₁ = spinup_truth
x₀ʳᵉᶠ = model.propagate(x₀, [0, T₁])
why it matters Without spinup, the truth carries noise from the synthetic IC. Filters then look great by accident — they are correcting an unphysical state, not climatological dynamics. Skip this phase by passing x0_ref=... from a previous run.

Phase 02 · ensemble centre

A small kick. Then chaos amplifies it.

A real-world background carries accumulated forecast error. To imitate that, we perturb x₀ʳᵉᶠ with a small Gaussian kick and let the model run for spinup_xb. Chaotic divergence does the rest — the result xᵇ sits at a different point on the attractor than the truth will. The distance ‖xᵇ − truth[0]‖ is the realistic background error the filter must correct.

input
x₀ʳᵉᶠ   // from Phase 1
add   pert_xb · 𝒩(0, I)  // from rng_xb
propagate over t ∈ [T₁, T₁ + T₂]   with   T₂ = spinup_xb
xᵇ = model.propagate(x₀ʳᵉᶠ + pert_xb · ε, [0, T₂])
tuning hint pert_xb sets the seed; spinup_xb sets how much chaos amplifies it. Their product determines ‖xᵇ − x₀ʳᵉᶠ‖. For Lorenz96 this saturates fast (hours of model time); for QG and SWE it can take days. Skip this phase by passing xb=....

Phase 03 · initial ensemble

Disperse N members around xᵇ.

The filter needs uncertainty around the centre, not just one state. Each ensemble member is born by perturbing xᵇ independently and propagating it for a short time so the perturbations enter the model's slow manifold. The result Xᵇ is the columnar matrix of N members at the same model time as the truth.

input
xᵇ   // from Phase 2
for k = 0 .. N_ens − 1:
    ε_k = pert_ensemble · 𝒩(0, I)  // from rng_ens
    Xᵇ[:, k] = model.propagate(xᵇ + ε_k, [0, T₃])
Xᵇ ∈ ℝn × N_ens   with   T₃ = spinup_ensemble
centring property Because each member only diverges for spinup_ensemble, mean(Xᵇ) ≈ xᵇ: the ensemble is centred on the offset background, not on the truth. That's what makes the experiment realistic. Skip this phase by passing initial_ensemble=....

Truth synchronisation

The truth catches up to ensemble time.

Phases 2 and 3 advance the ensemble by T₂ + T₃ in model time. So we propagate the truth by exactly the same amount, starting from x₀ʳᵉᶠ with no perturbation, to get truth[0]. Truth and ensemble are now anchored at the same instant — the filter can begin assimilating.

input
x₀ʳᵉᶠ
propagate(x₀ʳᵉᶠ, [0, T₂ + T₃])  // no perturbation, deterministic
truth[0]
then for k = 0 .. K − 1:
    truth[k + 1] = model.propagate(truth[k], obs_freq)
subtle but critical Since truth[0] ≠ xᵇ (Phase 2 perturbed and propagated; truth-sync did not), the filter sees a non-zero initial background error. Reusing precomputed x0_ref + xb + initial_ensemble across scenarios still costs the truth-sync propagation — but only that one.

Observation loop

Reality, sampled noisily.

For each step k, an observation operator opₖ (either fixed or rebuilt from rng_op) is applied to truth[k], and Gaussian noise drawn from rng_noise is added. The whole sequence y_0, ..., y_{K-1} is what the filter actually consumes.

for each step k
// pick or build the operator
opₖ = base_op   or   operator_factory(rng_op)
y_k = opₖ.apply(truth[k]) + noise.sample(rng_noise)
observations = [y_0, y_1, ..., y_{K-1}]
two scheduling modes operator_schedule='fixed' uses the same operator at every step (recommended for benchmarks: any RMSE difference is then attributable to the filter, not to varying obs networks). 'random' rebuilds opₖ each step from operator_factory.
