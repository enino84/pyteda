§ 01 models

The dynamical core. Every Model exposes a uniform contract — propagate, get_initial_condition, get_ngb, get_pre, create_decorrelation_matrix — so any analysis filter works against any model. Three concrete models ship: 1D Lorenz96, 1.5-layer Quasi-Geostrophic on a periodic plane, and shallow-water on the sphere. The QG model carries an internal subsystem of pluggable time integrators and boundary conditions.

§ 02 observation

Observation is split into two orthogonal abstractions: an ObservationOperator (how state maps to observation space, possibly nonlinear) and an ObservationNoise (the error covariance R, possibly dense). The Observation class composes both and exposes the legacy attributes (H_index, R, y) that all 10 filters consume — so the new system is a strict superset of the old.

§ 03 analysis

Ten ensemble filters share the abstract Analysis contract. perform_assimilation(background, observation) is the one method that matters; the rest are accessors. AnalysisFactory dispatches by string identifier so users write method='letkf', r={'q': 2, 'psi': 4} and the right class is built.

§ 05 simulation

The execution engine. Two modes: legacy (model + background + analysis + observation tuple) and the v2 path (Simulation.from_scenario(scenario, analysis)) that runs against a frozen Scenario. Optional flag store_diagnostics=True records spread, CRPS and rank-histogram counts at every step.

§ 06 experiments

The reproducibility layer. Scenario.generate builds the entire twin-experiment in three phases (x0_ref → xb → X_b) under a master seed, with truth synchronisation. Benchmark takes M scenarios × K methods × R runs and returns a BenchmarkResults with calibration diagnostics and plotters.

§ 07 io

Functional module — no public classes — exposing roundtrip helpers for the artifacts that scenarios depend on. netCDF by default, npz fallback. Format auto-detected by extension. get_data_dir() returns the user's chosen storage directory.

System wiring · how the pieces compose at runtime

Inheritance is shown as solid arrows. Composition (one object holds a reference to another) is shown as dashed arrows with a diamond head. Read it as: a Simulation drives a Background through an Analysis against an Observation; a Scenario freezes all of that for a single seeded experiment; a Benchmark orchestrates many Scenario × Analysis cells.
